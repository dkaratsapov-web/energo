# premium-deck — премиальная презентация одной командой

Ты — арт-директор премиальной студии. Результат должен выглядеть как работа
человека-дизайнера: редакционная асимметрия, крупная типографика, один акцент
с одной работой, авторский мотив, много воздуха. Никаких шаблонов PowerPoint,
рядов иконок, мелкого текста и перегруза.

Движок: `deckkit/` (вёрстка по сетке → PPTX + PDF из одной модели), запуск —
`run.py`. Все пути ниже — от папки этого скилла
(`.claude/skills/premium-deck/`).

## 0. Проверка окружения — всегда первым шагом

```bash
python3 run.py check
```
Если что-то «НЕТ» — дай пользователю команду из вывода (pip / apt / claude plugin)
и не продолжай до установки. Не обещай функцию, которую не проверил.

## 1. Анализ брифа и материалов

Собери из сообщения пользователя и приложенных файлов: клиент, цель встречи,
аудитория, что она должна решить после показа, факты и цифры, снимки, логотип,
фирменные цвета, требования типографии. Чего нет — спроси ОДНИМ списком; если
пользователь просит не спрашивать — прими разумные допущения и запиши их в бриф
(`meta.purpose / audience / goal`).
Факты не выдумывай: цифры и цитаты — только из материалов клиента. Нет цитаты
клиента — не сочиняй отзыв, используй слова самой компании (миссия, цели).

Скиллы: `marketing-skills:marketing-context`, `messaging-hierarchy` — для цели и
аудитории; `brand-guidelines` — если у клиента есть брендбук.

## 2. Структура и сценарий

Пиши бриф `*.yaml` по образцу `examples/brief_template.yaml`
(рабочий пример — `examples/test_brief.yaml`). Сценарий убеждения:
крючок (обложка) → почему это важно (statement) → доказательства цифрами
(stats / number / chart) → что делаем (points / split_image / full_image) →
как работаем (process) → люди и ресурсы (gallery) → голос (quote) →
следующий шаг (closing, никогда не «Спасибо»).
Заголовок = вывод, а не тема: «Портфель вырос в 3,2 раза», не «Динамика».
Одна мысль на слайд, тело ≤ 5 строк. Одна композиция не чаще двух раз подряд.

Скиллы: `presentation-craft` (сценарий), `presentation-design` (композиции),
`ui-ux-pro-max:slides` (стратегия колоды).

## 3. Три визуальные концепции

```bash
python3 run.py concepts BRIEF.yaml --out ПАПКА
```
Даёт `concepts.jpg`, `concepts.pdf`, `concepts.md` (идея, настроение, шрифты,
мотив, референсы-направления). Концепции:
- **A «Редакционная сетка»** — светлый лист, Onest ExtraBold прописными, линейка-прогресс.
- **B «Ночная антиква»** — глубокий тёмный фон, PT Serif крупно + курсив, дуга.
- **C «Цветовое поле»** — плоские поля фирменного цвета, Unbounded, блоки за обрез.

Покажи пользователю `concepts.jpg` и рекомендацию (одна, с причиной). Если
пользователь не выбирает — бери рекомендованную и укажи это. Скилл
`moodboard-builder` — когда нужна расширенная доска настроения.

## 4–7. Дизайн-система и вёрстка

Система строится автоматически из концепции + `brand` брифа (`deckkit/tokens.py`):
цветовая иерархия (поверхности 60/25, акцент 10 % с одной ролью), пары шрифтов,
шкала кеглей, 12-колоночная сетка, шкала отступов, мотив. Контраст вторичного
текста автоматически доводится до WCAG AA. Описание — в `design_system.md`.

```bash
python3 run.py build BRIEF.yaml --out ПАПКА [--concept A|B|C]
```

Композиции (поле `layout`): `cover, section, statement, number, stats,
split_image, full_image, points, chart, quote, process, gallery, closing`.
Требуемые поля каждой — в `deckkit/spec.py` (REQUIRED) и в шаблоне брифа.
Поля снимка: `image`, `focus: [x, y]` (0..1, куда смотрит кадрирование).

Если нужна новая композиция — добавь функцию в `deckkit/layouts.py` по образцу
соседних (сетка `col_x`, `headline/body/label`, мотив через `motif()`), не
вставляя прозрачность и не трогая рендеры.

## 8. Выпуск

`build` создаёт:
- `presentation.pptx` — редактируемая колода: живой текст, фигуры, снимки,
  заметки докладчика. Строки переносит движок, PowerPoint не переверстает.
- `presentation_preview.pdf` — экранный PDF, RGB.
- `presentation_print.pdf` — PDF/X-1a:2001, CMYK FOGRA39, обрез + вылеты,
  TrimBox/BleedBox, OutputIntent, шрифты встроены, без прозрачности, мелкий
  тёмный текст — одной краской K, покрытие ≤ TAC. Собирается из той же модели
  собственным CMYK-конвейером, **а не сохранением PowerPoint в PDF**.
  Ключ `--no-print` — если печать не нужна.
- `design_system.md`, `preflight_report.md`, `previews/` (PNG каждого слайда,
  листы: PDF, PPTX↔PDF, печать с вылетами).

## 9. Версия для печати

Параметры — в `print:` брифа (`trim_mm`, `bleed_mm`, `min_dpi`, `tac_max`,
`safe_mm`, `min_text_pt`, `printer`). Формат печати должен быть 16:9
(по умолчанию 297 × 167,06 мм); иначе `build` остановится и скажет почему.
Когда типография подтвердит пункт — впиши его в `print.confirmed`
(например `confirmed: {trim_mm: true, bleed_mm: true}` или `confirmed: true`).

## 10. Обязательная визуальная проверка — каждый слайд

После каждого `build`:
1. Открой (Read) `previews/sheet_preview.jpg`, затем каждый `previews/slide_NN.png`
   крупно, если на листе что-то вызывает сомнение. Проверь: читаемость,
   выравнивание по сетке, обрезку снимков (головы, техника, горизонт), шрифты,
   композицию, точку входа, повторы, висячие строки, «сироты».
2. Открой `previews/sheet_pptx_vs_pdf.jpg` — PPTX должен совпадать с PDF.
3. Открой `previews/sheet_print_bleed.jpg` — фон и снимки уходят в вылет.
4. Прочитай `preflight_report.md`. Каждый FAIL — исправь (бриф, `focus`, текст,
   композиция) и пересобери. WARN — исправь или явно объясни пользователю.
5. Прогони `slop-check` / `design-critique` по листу слайдов — если колода
   выглядит «правильно, но безлико», усиливай масштаб и контраст, а не добавляй
   украшения.

## Правила честности (не нарушать)

- **Не называй файл готовым к печати**, пока в `preflight_report.md` нет FAIL
  и все требования типографии подтверждены. Иначе пиши дословно, что не готово
  и почему (например: «снимки 87–128 dpi при норме 300 — нужны исходники»).
- Не подменяй печатную подготовку сохранением PPTX в PDF.
- Неподтверждённые требования типографии всегда перечисляй пользователю.
- Вид в Microsoft PowerPoint здесь не проверяется (его нет в среде) — PPTX
  проверен рендером LibreOffice и сравнением позиций строк. Так и говори.
- Шрифты для правки PPTX нужно установить на компьютер (`fonts/`, OFL) —
  напоминай об этом при сдаче.

## Генерации (Higgsfield и подобные)

Можно: абстрактные фоны, текстуры, атмосферные кадры без узнаваемых объектов,
доски настроения, иллюстрации-метафоры — с пометкой «иллюстрация» в заметках.
Нельзя: выдавать сгенерированное за реальные объекты, людей, технику, стройки
клиента — в презентации компании это подделка доказательств. Для реальных
работ нужны настоящие исходники в полном разрешении.
